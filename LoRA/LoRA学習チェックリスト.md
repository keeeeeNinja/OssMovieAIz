# LoRA学習 失敗しないためのチェックリスト

Extra_Long_Lashes LoRA（2026-03-25）の失敗から導いた対策まとめ。

---

## 失敗した根本原因と対策

### 1位：背景除去をしていなかった（最大の原因）

データセットの背景が壁・棚・木の机・バスルームなどバラバラだった。
Fluxが「どの背景が正解か」に学習コストを使ってしまい、製品の特徴を覚えられなかった。

**対策**: 全画像を背景除去して白背景に統一してから学習する。

---

### 2位：フレーミングが不均一だった

製品が画面の10%しか占めていない画像が複数混入していた。

**対策**: 学習前に全画像を目視チェックし、製品がフレームの **60〜80%以上** を占めているものだけ使う。

---

### 3位：キャプションの多様性がなかった

21枚全部が似たような文章構造で、Fluxに「同じ画像」と認識されやすかった。

**対策**:
- 短いもの・長いもの・角度に着目したもの・素材感に着目したものと**バリエーションをつける**
- トリガーワードは学習前にFluxがその単語に何を想起するか確認する

---

### 4位：学習前に「ベースモデルが何を知っているか」確認しなかった

step0サンプルを見て初めて「Fluxは銀チューブ製品を既によく知っている」とわかった。
LoRAで上書きすべき差分を把握せずに学習を始めてしまった。

**対策**: **学習開始前にベースモデルでテスト生成**し、LoRAで上書きすべき差分を把握してからキャプション・ステップ数を決める。

---

## 次回のチェックリスト

### 学習前
- [ ] 全画像の背景を除去（白背景統一）
- [ ] 製品がフレームの60%以上を占めているか目視確認
- [ ] 極端に小さい・遠い・部品のみの画像を除外
- [ ] ベースモデルでトリガーワードをテスト生成して確認
- [ ] キャプションに短文・長文・角度違いのバリエーションあり
- [ ] JoyCaptionを使う場合は生成後に全キャプションを目視確認（誤カテゴリーでないか）

### 学習中
- [ ] step500のサンプルで方向を確認（おかしければ早期中断）
- [ ] lossが極端に高い／低いままでないか確認

### 学習後
- [ ] 複数のプロンプトでテスト生成（トリガーワードあり・なし両方）
- [ ] step500・1000・最終の3チェックポイントを比較
- [ ] 前回LoRAと並べて比較生成する

## 製品LoRAのデータセット品質基準

| 項目 | 基準 |
|------|------|
| 背景 | 白または単色（除去済み推奨） |
| 製品の占有率 | フレームの60%以上 |
| 枚数 | 15〜30枚（品質が高ければ少なくてOK） |
| 角度の多様性 | 正面・斜め・横・クローズアップを含む |
| 照明 | 均一（影が強すぎないもの） |
| 除外すべき画像 | 製品が小さすぎる・部品のみ・ピンぼけ |

---

## JoyCaptionを使う場合の注意

- プロンプトに製品カテゴリーを明示する（例: "eyelash enhancing serum" と書く）
- 生成後に全キャプションを読んで、誤カテゴリー（例: mascara）になっていないか確認
- 疑わしい場合は手書きキャプションに差し替える

## ディレクトリ構成（RunPod）

```
/root/datasets/<ProductName>/   ← ローカル（Pod再起動で消える）
/root/ai-toolkit/               ← ローカル（Pod再起動で消える）
/workspace/output/<lora_name>/  ← Network Volume（永続）
/workspace/run_<lora_name>.py   ← Network Volume（永続）
```

**ポイント**: データセットとai-toolkitはローカルに置く。LoRA出力だけNetwork Volumeに保存する。
両方をNetwork Volumeに置くとディスククォータエラーでLoRAが保存できなくなる。
